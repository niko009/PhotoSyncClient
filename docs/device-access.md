# Доступ по телефону без Google — протокол v2

Реализовано в локальной версии 0.2.0-beta, 2026-08-31. Публичный сервер не развёрнут.

## Обычный запуск

Аккаунт и Google не нужны. При первом запуске приложение создаёт случайный
256-битный ключ установки в Android noBackupFilesDir. Из него через HMAC-SHA256
выводятся отдельный UUID и секрет для каждого нормализованного адреса сервера.
Схема, домен и порт входят в адрес: HTTP/HTTPS и разные домены — разные пространства.
Регистрировать ID вручную не нужно; нужен доступный обновлённый сервер.

Приложение передаёт:

- X-PhotoSync-Device: UUID;
- Authorization: Bearer <64 шестнадцатеричных символа>.

Секрет нельзя публиковать, помещать в URL или логи. На сервере хранится только его
SHA-256. UUID сам по себе не даёт доступа. У кого есть копия секрета, тот имеет
доступ: это не аппаратная аттестация телефона и не сквозное шифрование.

Регистрация POST /api/devices/register допускает новый UUID с новым секретом.
Повторная регистрация существующего UUID требует правильного секрета.
Старые UUID без секретов не могут быть присвоены первым посетителем.
Регистрация не назначает владельца или администратора всей установки.

Все списки, альбомы, загрузки, проверки хеша, превью, скачивание и статистика
ограничены устройством из проверенной сессии. Подмена UUID в теле или ID в URL
не меняет владельца запроса. /api/admin/dashboard тоже ограничен этим устройством;
старый /admin больше не является открытой общей админкой и требует заголовков.

GET /api/server/info и GET /api/server/capabilities публичны. Последний возвращает
device_auth=true, google_auth=false, family_sharing=false, protocol_version=2.
Клиент отказывается синхронизироваться с сервером без device_auth.

## Сброс, переустановка и смена сервера

- Перезапуск и обновление APK с сохранением данных сохраняют ключ.
- Удаление приложения, очистка данных и заводской сброс удаляют ключ.
- Новый ключ означает новое пространство. Старые файлы на сервере НЕ удаляются.
- Возврат к прежнему адресу с прежним ключом возвращает прежнее пространство.
- Локальные списки и миниатюры разделены по идентичности устройства и сервера.
- Автоматического восстановления, экспорта ключа и привязки Google сейчас нет.
- Root-доступ или доступ к файлам сервера выходит за пределы этой изоляции.

Для старой версии 0.1.0 нет безопасного автоматического переноса владения:
её ID не был доказательством личности. Старый кэш оставлен на диске, но новая
версия не показывает и не присваивает его. Существующие серверные файлы доступны
владельцу файловой системы; перенос через отдельную подтверждённую процедуру
нужно согласовать отдельно. Не очищайте старые данные ради обновления.

## Обновление сервера

Перед обновлением остановить загрузки и сделать согласованный бэкап SQLite вместе
с оригиналами. Инициализация добавляет device_credentials, заменяет глобальный
уникальный индекс SHA-256 индексом (DeviceId, AlbumId, Sha256), не удаляя строки.
Повторный запуск допустим. Одинаковый файл можно хранить независимо на двух
телефонах и в двух альбомах. Новые папки устройств используют полный UUID;
существующие пути автоматически не переименовываются.

Google и семья позже должны привязывать это пространство к проверенному аккаунту
только при доказанном владении текущим ключом, а не по присланному UUID.
План: [семейный доступ](family-sharing.md).

## Границы безопасности

Публичным адресам нужен HTTPS. HTTP разрешён клиентом только для частных IPv4,
localhost и .local в доверенной сети: в такой сети перехват трафика всё ещё возможен.
Редиректы отключены, чтобы не пересылать авторизацию на другой адрес.

Автоматическая регистрация пока открыта. Это не готовый платный публичный сервис:
до публикации нужны ограничения регистрации/квоты, защита от массовых загрузок,
управление потерянными устройствами, бэкап и проверки Docker/Windows-хранилища.
