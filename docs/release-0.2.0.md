## Реализовано

- Молочная светлая и тёплая тёмная темы, терракотовый акцент, заголовки с засечками.
- Векторный знак фотоальбома, обложки альбомов, отдельная вкладка сохранения.
- Сетка фото, просмотр, скачивание оригинала внутрь приложения.
- Настройки адреса сервера и поведения после загрузки; подтверждение удаления.
- Русский, английский и румынский интерфейсы.
- Реальные состояния подключения и ошибок вместо декоративного «подключён».
- Автоматический секрет устройства; изоляция серверных данных и локального кэша.
- Совместимые с Android 8+ миниатюры без растягивания исходного соотношения сторон.

Сервер и APK нужно обновлять вместе. Подробности, ограничения сброса телефона и
перехода со старой версии: [доступ устройства](device-access.md).

## Пока не реализовано

Google OAuth, привязка аккаунта, восстановление после потери ключа, семейные
приглашения и права доступа, автоматическое наблюдение за папками и фоновая
очередь с повторными попытками. Настройка OAuth сама по себе эти функции не включит.
Вход не требуется для текущего режима.

Выбор файлов сейчас выбирает фотографии, не видео. «Обновить» перечитывает сервер,
но не повторяет неудачные загрузки. Скачивание кладёт оригинал в закрытые файлы
приложения, не в системную галерею. «Убрать из локального списка» не удаляет оригинал
в галерее или на сервере. Сжатие создаёт дополнительную копию внутри приложения.

## Сборка и проверка

Используются Gradle wrapper, JDK 17 и SDK 34. APK подписан тестовым debug-ключом;
для публичного релиза нужен постоянный release-ключ. Не удалять установленное
приложение при несовпадении подписи: это приведёт к потере ключа доступа.

APK: `output/releases/photosync-0.2.0-beta.apk` (8 212 127 байт).
SHA-256: `1ac3d63ac709398daec6aa38b48ceda8d566b06e32a892f248b3d385ef5885a5`.
Подпись проверена apksigner (v2).

Результаты проверок:

- Сервер: 19/19 тестов, включая изоляцию устройств и обновление старой схемы.
- Android JVM: 10/10 тестов.
- Android API 35 через ADB: 3/3 UI-теста и 1/1 сквозной тест с навигацией.
- Android lint: 0 ошибок, 33 предупреждения (включая старые ресурсы и версии).
  Старый lint также печатает предупреждения о Kotlin metadata; обновление всего
  Android build stack не входило в этот редизайн.
- NuGet audit: известных уязвимых пакетов в текущих источниках не найдено.
- Сквозной Android → .NET тест прошёл: альбом с русским названием, загрузка,
  побайтно идентичное скачивание, недоступность файла второму устройству.
- Сохранены пять снимков настоящих Compose-экранов на Android API 35.
  Это тестовая сессия с синтетическим одноцветным PNG, а не фотографии пользователя.

Сквозной тест запускается отдельно на Android с аргументом
`photosyncTestServer=http://10.0.2.2:5188` и изолированным локальным сервером.
Без этого аргумента он пропускается; пользовательский сервер для теста не используется.

На этой Windows-машине Java loopback не работает через виртуализированную Temp.
Временный обход для одного процесса — JAVA_TOOL_OPTIONS с
-Djdk.net.unixdomain.tmpdir=<абсолютная папка output/jvm внутри проекта>.
При нехватке памяти сборка и эмулятор запускаются по очереди; глобальные
настройки Java и Windows не менялись.
Основание: [OpenJDK](https://mail.openjdk.org/pipermail/nio-dev/2023-March/013297.html),
[Gradle JVM configuration](https://docs.gradle.org/current/userguide/config_gradle.html).

Нативная SQLite-зависимость закреплена на 2.1.13 вместо уязвимой 2.1.11.
[Пакет](https://www.nuget.org/packages/SQLitePCLRaw.lib.e_sqlite3/2.1.13).

## Заметка о локальной dev-базе

Обнаружено, что ранние тесты использовали dev-строку подключения из-за слишком
раннего чтения конфигурации в Program.cs. В локальной dev-базе могут оставаться
служебные записи этих запусков; автоматическая очистка не выполнялась.
Файлы пользователя не удалялись. Теперь строка подключения разрешается через DI
после test-host overrides; отдельный тест проверяет абсолютный путь временной базы.
Для дальнейших интеграционных проверок используется отдельная output/smoke-v2.

Публикация артефактов в репозитории сайта не обновляет сервер PhotoSync и
канонический репозиторий его исходников. Текущий статус сайта указан выше.
