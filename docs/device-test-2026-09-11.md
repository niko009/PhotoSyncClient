# PhotoSync: проверка на физическом телефоне, 11 сентября 2026

Проверка выполнена на Xiaomi M2101K6G с Android 13 (API 33), подключённом по ADB. На телефон в конце установлена штатная release-сборка `0.6.8-beta` (`versionCode 6008`) поверх существующего приложения без очистки данных. Настройки, идентичность устройства, альбомы и локальный кэш сохранились.

Итог: основные клиент-серверные сценарии работают, найденные во время проверки дефекты исправлены и повторно проверены. Сборку пока нельзя считать полностью production ready: не проверены восстановление резервной копии и реальный внешний тракт для многогигабайтного видео, нет возобновляемой загрузки, а на тестовом телефоне почти заполнен накопитель.

## Что проверено

- Release и debug APK собираются на Gradle 8.2, AGP 8.2.2, Kotlin 1.9.22; Android unit tests и `lintDebug` проходят без ошибок.
- Серверные тесты: **45/45** в основном наборе и **3/3** в оставшемся legacy-наборе.
- Android: **23 unit-теста** прошли. Debug и release APK, а также instrumentation APK успешно собраны.
- Изолированный on-device smoke test передал фото 256 КиБ и видео 32 МиБ потоково, скачал их обратно, сверил SHA-256, проверил HTTP Range (`206`), список файлов альбома и изоляцию второго устройства. Результат: [device-smoke-result-2026-09-11.json](audit/device-smoke-result-2026-09-11.json).
- Проверены запуск, остановка процесса, холодный старт, уход в фон и возврат. Состояние и альбомы сохранились; crash и ANR в истории процессов отсутствуют.
- Проверены главный экран, настройки, семейный раздел, папка, полноэкранный просмотр, системный Back, custom/HTTPS deep links и повторная доставка ссылки в уже открытое приложение.
- Проверен импорт одного изображения через системный `ACTION_SEND`: клиент принял URI, показал `Выбрано: 1` и список папок. Загрузка тестового изображения была отменена, поэтому серверные данные пользователя не менялись.
- Release APK установлен поверх тестовой сборки. На устройстве нет флага `DEBUGGABLE`, версия и данные сохранились, приложение запустилось. APK подписан сертификатом PhotoSync с SHA-256 `0d3539a66b5938b4cabbd7d76acee286877a5e46648b4b8c6d4236f5c8b9862d`.
- Публичный сервер `https://photosync.bacus.dev` отвечает на `/health`; реальные API-запросы телефона во время диагностики завершались HTTP 200. 8 сентября наблюдался кратковременный Cloudflare 502, после чего сервер восстановился.

## Дефекты, исправленные по результатам проверки

- Полноэкранный просмотр выбирал недоступный старый локальный URI и показывал логотип вместо уже видимой в сетке миниатюры. Просмотрщик теперь пробует исходный URI, затем кэшированный thumbnail. Исправление подтверждено на телефоне.
- Повторный deep link мог создавать ещё один экземпляр `MainActivity`. Добавлен `singleTop`; повторная ссылка доставляется существующему экрану, размер task остаётся 1.
- Семейный экран и семейный блок настроек были частично захардкожены на английском. Добавлены ресурсы для русского, румынского и базового языка, включая роли и ошибки.
- При старте выполнялись два одинаковых автоматических refresh. Удалён лишний повтор, чтобы не создавать ненужные запросы и скачивания.
- Включена поддержка системного predictive Back для Android 13+.

## Оставшиеся production-блокеры

1. Резервное копирование базы и оригиналов не было восстановлено в отдельном окружении. Пока не проверены restore, сверка количества файлов и SHA-256, нельзя обещать сохранность при отказе сервера.
2. Лимит приложения установлен в 2 ГиБ, а потоковая передача проверена на 32 МиБ. Нужно испытать через Cloudflare и весь production proxy тракт видео выбранного максимального размера, включая таймауты и свободное место. Возобновления загрузки после обрыва с позиции байта пока нет.
3. Нужны эксплуатационные проверки заполненного диска сервера, недоступного storage mount, аварийного завершения во время публикации и последующей автоматической сверки файлов с SQLite.
4. У телефона свободно около **988 МиБ**, раздел `/data` показывает 100% использования после округления. Это может сломать staging большого видео и работу других приложений; перед большими испытаниями нужно освободить место.
5. MIUI отклонил установку instrumentation APK с `INSTALL_FAILED_USER_RESTRICTED`. APK собирается, но Compose UI suite на устройстве не запускался; его заменили ручные сценарии и debug-only smoke activity. Для полного прогона нужно разрешить установку через USB в параметрах разработчика MIUI.
6. Нужны отдельные испытания двух реальных телефонов и двух Google-аккаунтов: приглашение, View/Contribute, отзыв прав, одинаковые имена альбомов, выход и повторный вход. Выход из Google на этом личном телефоне во время проверки не выполнялся.
7. Нужна явная процедура восстановления устройства после удаления приложения или очистки его данных. Закрытая регистрация защищает сервер, но потеря device secret без процедуры восстановления оставит установку без доступа.
8. Публичный manifest обновления всё ещё указывает на `0.6.7`; сервер и APK `0.6.8-beta` не развёртывались и не публиковались этой проверкой.

## Решение по Google-аккаунту

Доступ этого телефона к его приватным альбомам остаётся привязан к локальному device secret, поэтому выход из Google или вход в другой аккаунт не скрывает уже доступные телефону приватные альбомы. Это соответствует выбранному требованию. Пока есть неотправленная очередь, смена аккаунта блокируется, чтобы файлы не попали в неверный контекст. Перед выпуском нужно дополнительно проверить этот сценарий с двумя тестовыми аккаунтами и определить, какие семейные права должны оставаться после смены пользователя.
