# Изменения после аудита — 7 сентября 2026

Изменения находятся в рабочей копии. Публичный сервер не обновлялся, release APK не публиковался. Production readiness пока не подтверждена. Результаты проверки на физическом Android-устройстве: [device-test-2026-09-11.md](device-test-2026-09-11.md).

## Исправлено

- Перерегистрация существующего UUID требует действующего секрета. Неизвестным клиентам запрещено заменять секрет; старые записи без секрета больше нельзя захватить по UUID.
- Для публичной установки регистрация новых устройств по умолчанию закрыта. Оператор явно включает `PhotoSync:AllowDeviceEnrollment`; действует `MaxDevices=5`. Уже зарегистрированным устройствам открытая регистрация не нужна.
- Дедупликация проверяет размер и SHA-256 физического оригинала. Отсутствующий или повреждённый оригинал даёт ошибку повторной загрузки и `exists=false` при check, вместо ложного успеха и разрешения очистить телефон. Автоматического ремонта повреждённых оригиналов пока нет.
- После сбоя записи SQLite повтор использует оставшийся идентичный файл, не создавая новую копию. Оригиналы не удаляются и не перезаписываются. Без повторной попытки такой файл пока остаётся вне базы: это частичное восстановление, не полноценная сверка при старте.
- Перед публикацией заново читается состояние альбома. Это закрывает использование старого SharingMode/ArchivedAtUtc во время длительной загрузки; полная атомарность с конкурентным отзывом прав ещё требует отдельной проверки.
- Журнал не сохраняет тела семейных маршрутов, токены приглашений в пути, тела CSRF-ответов, query string и полный текст исключений.
- Сервер выдаёт файлы потоково с поддержкой byte ranges.
- Android хеширует, отправляет и скачивает медиа блоками; основные сценарии больше не держат видео целиком в памяти. Скачивание публикуется из временного файла только после завершения. В галерейной сетке не скачиваются оригиналы видео и изображения больше 10 МиБ в качестве превью; для них пока нет миниатюры с сервера.
- Лимит одного файла по умолчанию — **2 ГиБ**, согласован с лимитами Kestrel и multipart. Проверка прокси обязательна: этот параметр приложения не отменяет внешних ограничений.
- Копирование импорта перенесено на IO, staging-файл синхронизируется на диск; очередь сохраняется через проверяемый commit до обновления состояния. Частичная копия при ошибке удаляется.
- Синхронизация не требует внешнего интернета, если есть активная сеть. Worker учитывает ожидающие/ошибочные файлы и несозданные альбомы; новые задания не отменяют текущую передачу. Постоянные ошибки пока тоже повторяются с backoff.
- Ошибка отправки больше не удаляет старую запись только потому, что её URI похож на Photo Picker URI.
- Альбомы загружаются по server album ID, а не группируются по имени. ID сохраняется в локальном кэше. Миграция уже смешанного кэша старой версии требует проверки на реальном устройстве.
- При непустой очереди смена сервера, вход в другой аккаунт и выход блокируются с сообщением в настройках. Это временное безопасное ограничение; отдельные приостанавливаемые очереди аккаунтов пока не реализованы.
- CI запускается на push/PR и вручную, включает серверные тесты и Android unit tests/build. Сам workflow удалённо не запускался.

## Результаты проверки

- Сервер: **45 тестов прошли**, включая защиту от замены секрета, закрытую регистрацию, cap устройств, отсутствующий/повреждённый оригинал, повтор после ошибки SQLite, byte ranges и отсутствие синтетических секретов в журнале.
- Android: **23 теста прошли**. Новый HTTP-тест передаёт 32 МиБ через клиент с chunked request, скачивает обратно и сверяет SHA-256; источник запрещает чтение блоками больше 64 КиБ. Два теста проверяют запрет смены контекста при непустой сохранённой очереди.
- Gradle обновлён до 8.2, AGP до 8.2.2, Kotlin до 1.9.22 и Compose compiler до 1.5.8. Unit tests, `lintDebug`, debug/release APK и instrumentation APK собираются чисто.
- Версия повышена до `0.6.8-beta` (`versionCode 6008`). Release APK подписан штатным ключом, установлен на физический телефон поверх прежней версии без очистки данных и проверен как non-debuggable.
- Debug-only smoke test запущен на Xiaomi с Android 13: потоковая передача и SHA-256 для 32 МиБ, Range 206, список альбома и изоляция устройства прошли. Установка instrumentation APK заблокирована настройкой безопасности MIUI `INSTALL_FAILED_USER_RESTRICTED`, поэтому Compose UI suite на телефоне не выполнялся.
- `git diff --check` без ошибок. Скрипт `scripts/verify-local.ps1` прошёл синтаксическую проверку PowerShell.

Исходная Java 17 в `JAVA_HOME` неполна. Рабочая установка для проверки: `C:/Users/m.bacus/.jdks/jbr-17.0.14`. Сбой AF_UNIX в Windows обойдён для процесса проверки через несуществующий `jdk.net.unixdomain.tmpdir`, заставляющий JDK использовать TCP для локальных pipes. Глобальные переменные среды не менялись. ## Перед обновлением публичного сервера

1. Проверить резервную копию базы и оригиналов и восстановление в отдельное хранилище.
2. Проверить лимит запросов и таймауты внешнего прокси. Передача 2 ГиБ через публичный адрес не тестировалась. Возобновления upload с произвольного смещения пока нет; HTTP chunked framing не означает resumable upload.
3. Оставить `PhotoSync__AllowDeviceEnrollment=false`. Для подключения нового телефона оператор временно включает регистрацию только при ограничении доступа доверенными клиентами на прокси. Открытая регистрация без такого ограничения всё ещё позволяет постороннему занять свободное место устройства.
4. Установкам, потерявшим секрет, нужна отдельная процедура восстановления, а не замена секрета по UUID. Действующая установка с прежним секретом продолжит работу.
5. Старые журналы могли уже содержать токены; изменение кода не редактирует существующие файлы журнала.

Полные результаты и оставшиеся аппаратные сценарии записаны в [отчёте проверки устройства](device-test-2026-09-11.md).

По аккаунтам рекомендовано оставлять локально скачанные копии доступными на доверенном телефоне, а новые серверные операции связывать с текущим аккаунтом. Модель доступа после выхода в этой итерации не переделывалась; текущее поведение доверия устройству сохранено. Нужно отдельно реализовать и проверить явное разделение локальной библиотеки, серверных прав и приостановленных очередей без потери старых альбомов.

Остаются также восстановление повреждённого JSON очереди, полноценная сверка файлов с SQLite, мониторинг правильного mount и свободного места, атомарный отзыв прав, испытания нехватки диска/падения процесса, сохранение исходной даты съёмки и обновление инструментов lint. Эти ограничения нельзя считать закрытыми только на основании зелёных unit-тестов.
